# 新祥编程老师渠道与网页版作战图

## 1. 背景与结论

本作战图用于承接 2026-06-28 朋友访谈反馈，并把老师渠道、联名能力、网页版体验和后续白标能力拆成可按顺序执行的计划。

具体产品方案见：`docs/zhimeng-teacher-channel-web-product-plan.md`。本文件负责阶段顺序、闸门和处理结论；产品方案负责用户角色、页面、流程、字段、MVP 范围和验收口径。

朋友反馈：

- 编程授课老师可以成为新祥编程的重要销售渠道，由老师推广产品并赚取佣金。
- 产品需要支持老师自己定义产品名称或 Logo，提升老师推广意愿。
- 产品需要提供网页版，降低实施、安装和首次体验成本。

处理结论：

- 采纳老师渠道方向，但第一阶段定义为“老师渠道 MVP”，不直接做重白标。
- 采纳品牌自定义诉求，但第一阶段只做“新祥编程 x 老师/机构”的联名展示、订单归因和报告署名。
- 优先建设网页版体验入口，因为它直接降低下载、安装、系统拦截和老师演示成本。
- 完整白标/OEM 只在渠道验证成立后开放，并要求最低销量、年服务费或单独定制费。

当前执行口径：

> 先让老师发一个自己的链接，家长点开即可体验、注册、付款；我们能追踪来源、计算佣金、复盘作品完成和退款风险。

## 2. 总体路径

执行顺序不可随意跳跃。每一阶段通过后，再进入下一阶段。

| 阶段 | 名称 | 核心目标 | 主要产物 | 进入下一阶段条件 |
| --- | --- | --- | --- | --- |
| 0 | 合规与边界 | 明确哪些老师能合作、哪些不能返佣 | 渠道合作边界、佣金口径、风险提示 | 合作对象和佣金规则可对外说明 |
| 1 | 建账与归因 | 每一单能知道谁带来、赚没赚钱 | 推荐码、订单来源、佣金字段、利润看板 | 运营台和表格可记录渠道成本 |
| 2 | Web 体验入口 | 降低首次体验成本 | Web 编辑器体验页、注册登录、授权检查 | 老师可发链接让家长打开体验 |
| 3 | 老师联名页 | 让老师有推广身份和成交页面 | 老师专属落地页、Logo/头像、推荐语、FAQ | 3-5 个老师可使用专属链接 |
| 4 | 小样本试销 | 验证老师是否真能带来付费家庭 | 3-5 位老师、每人 5-10 个家庭、数据复盘 | 单老师至少 2 个真实付款家庭 |
| 5 | 渠道包标准化 | 把成功动作打包复制 | 渠道包、海报、讲解稿、3 个项目材料、结算 SOP | 至少 1-2 个渠道愿意付费拿包 |
| 6 | 项目包配置 | 允许老师定制交付内容，不改底层品牌 | 老师项目包名称、作品路径、报告署名 | 老师复购或持续带单成立 |
| 7 | 机构版/OEM 评估 | 判断是否值得做完整白标 | OEM 报价、品牌责任、售后边界、最低销量 | 有渠道愿意为定制和维护付费 |

## 3. 阶段 0：合规与边界

目标：先防止渠道跑偏。

必须遵守：

- 不把在职中小学教师作为返佣推广对象。
- 不承诺学校官方合作、考试评级、竞赛结果或升学效果。
- 不用“Scratch 官方”作为销售背书。
- 不做暗返、私下红包或无法入账的佣金。
- 所有付费权益继续由服务端授权判断，不能靠前端隐藏按钮控制。

优先合作对象：

- 自由编程老师。
- 少儿编程小机构。
- 亲子社群主。
- 素质教育 KOC / KOL。
- 有少儿编程内容能力的社群运营者。

阶段产物：

- 渠道合作边界说明。
- 推荐佣金规则。
- 渠道候选名单。
- 不合作对象黑名单口径。

## 4. 阶段 1：建账与归因

目标：先保证每一单能算清楚，不急着扩大。

必须具备的字段：

| 字段 | 用途 |
| --- | --- |
| referrer_code | 老师/渠道推荐码 |
| referrer_name | 老师或机构展示名 |
| source_type | 私域、转介绍、KOL/老师、渠道、投放 |
| landing_page_id | 专属落地页或活动页 |
| package_type | 年卡、7 天陪跑包、30 天作品营、渠道包 |
| commission_cents | 佣金成本 |
| delivery_cost_cents | 交付成本 |
| support_cost_cents | 客服成本 |
| first_project_done | 是否完成第一个作品 |
| refund_risk | 退款风险 |

当前已有基础：

- `docs/zhimeng-seed-user-tracking.md` 已要求记录订单来源、佣金成本、获客成本、交付成本、客服成本和预估利润。
- `website/ops.html` 已有来源、套餐、佣金、成本、利润和跟进字段。

补齐顺序：

1. 先在种子用户表和运营台人工记录老师来源。
2. 再做推荐码或链接参数。
3. 最后做自动佣金结算，不在试销前投入复杂后台。

阶段通过标准：

- 任何一笔老师推荐订单，都能回看来源、套餐、佣金、交付成本和预估利润。
- 运营能按老师维度汇总付款数、退款数、完成作品数和佣金。

## 5. 阶段 2：Web 体验入口

目标：老师发链接即可演示和体验，减少下载、安装、系统安全拦截导致的流失。

第一版范围：

- Web 端访问编辑器。
- 注册和登录。
- 拉取授权状态。
- 未付费用户进入有限体验。
- 已付费用户进入完整基础编辑器。
- 支持本地导入和导出作品。
- 引导用户购买年卡或 7 天陪跑包。

第一版不做：

- 云保存。
- 班级管理。
- 老师后台。
- 多机构隔离。
- 完整白标域名。
- 自动支付到账确认。

验收指标：

| 指标 | 目标 |
| --- | ---: |
| 老师发链接到家长打开体验 | >= 60% |
| Web 打开到注册 | >= 30% |
| 注册到创建订单 | >= 20% |
| Web 体验后愿意付款 | 首批老师样本中有真实成交 |
| 因安装问题流失 | 明显低于桌面客户端下载链路 |

桌面端定位：

- 桌面客户端继续作为正式创作和稳定交付形态。
- Web 端先承担体验、演示、老师推广和低摩擦转化。

## 6. 阶段 3：老师联名页

目标：满足老师“这是我的推荐/我的体验营”的心理需求，同时避免重白标。

联名页第一版：

- 页面标题：`新祥编程 x XX老师`
- 展示老师头像或机构 Logo。
- 展示老师推荐语。
- 展示适合年龄、作品案例、价格和开通说明。
- 使用老师专属推荐码。
- 家长可从页面进入 Web 体验或下载桌面端。
- 付款后订单绑定老师来源。

联名页不改：

- 产品主体仍为新祥编程。
- 账号体系仍为新祥编程。
- 支付和授权仍走新祥编程服务端。
- 客服、退款和开通规则仍按新祥编程统一口径。
- AGPL 源码披露和 Scratch 关系说明不被老师自定义覆盖。

阶段通过标准：

- 3-5 个老师能拿到可对外发送的专属链接。
- 家长不会误以为是 Scratch 官方或学校官方产品。
- 运营能按老师维度查看转化和佣金。

## 7. 阶段 4：小样本试销

目标：用真实数据判断老师渠道是否值得继续投入。

试销设计：

| 项目 | 要求 |
| --- | --- |
| 老师数量 | 3-5 位 |
| 每位老师触达家庭 | 5-10 个 |
| 主推路径 | Web 体验 -> 年卡 199 元 -> 7 天陪跑包 699 元 |
| 老师材料 | 专属链接、海报、话术、FAQ、3 个作品案例 |
| 复盘周期 | 7 天一轮 |

通过标准：

- 每位老师至少带来 2 个真实付款家庭，或明确证明某类老师不适合。
- 老师推荐订单退款率不高于私域订单。
- 至少 50% 付款家庭能完成第一个作品。
- 客服和交付没有明显失控。
- 老师愿意二次推广或升级渠道包。

暂停标准：

- 老师只愿意拿佣金但不愿意解释产品。
- 家长大量误解为直播课、一对一课或学校课程。
- Web 体验转化不如桌面链路，且主要问题不是安装成本。
- 佣金后年卡利润为负，陪跑包也无法加购。

## 8. 阶段 5：渠道包标准化

目标：把能成交的动作打包成 4999 元渠道/机构启动包。

渠道包建议内容：

- 20 个家庭体验名额或激活名额。
- 3 个新手项目材料。
- 老师联名页。
- 一套海报和朋友圈文案。
- 15 分钟讲解稿。
- 家长 FAQ。
- 推荐码和佣金结算规则。
- 每周一次轻量渠道答疑。

渠道包不包含：

- 完整班级管理。
- 私有部署。
- 独立 App 包。
- 老师无限自定义品牌。
- 新祥编程承担老师自己的课程交付责任。

通过标准：

- 成交 1-2 个 4999 元渠道包。
- 单个渠道包 30 天内带来追加家庭用户。
- 渠道成交不依赖创始人逐个深度解释。

## 9. 阶段 6：项目包配置

目标：满足老师差异化交付诉求，同时不触碰完整白标复杂度。

可开放：

- 项目包名称。
- 项目包封面。
- 3-5 个作品任务。
- 老师/机构署名。
- 完成报告中的老师 Logo。
- 专属结业截图或作品展示页。

暂不开放：

- 修改安装包名称。
- 修改 App 图标。
- 自定义授权逻辑。
- 自定义支付通道。
- 自定义源码披露口径。

通过标准：

- 老师使用自定义项目包后，作品完成率提升。
- 自定义内容不会增加显著客服成本。
- 老师愿意为项目包配置或渠道包续费。

## 10. 阶段 7：机构版/OEM 评估

只有同时满足以下条件，才启动完整白标或 OEM：

- 已有稳定老师/机构渠道带单。
- 至少一个机构愿意支付定制费、年服务费或明确最低销量。
- 已明确品牌、售后、退款、数据和 AGPL 源码披露责任。
- 已评估安装包签名、图标、产品名、官网、客服和更新链路成本。

OEM 必须单独报价，不走普通推荐佣金。

建议进入门槛：

- 单机构年服务费 >= 9999 元，或
- 单机构预付名额 >= 100 个，或
- 定制费覆盖开发、测试、签名、发布和维护成本。
