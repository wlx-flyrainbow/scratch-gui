# 新祥编程 AGPL 产品战略实施计划

## 1. 执行结论

新祥编程不应把 AGPL 视为商业化阻碍，而应把它作为产品架构边界：

> 开源编辑器，闭环服务；免费代码，收费结果。

核心编辑器、客户端改造、构建链路和对应源码按 AGPL 要求公开。商业护城河放在服务端权益、AI 能力、素材授权、项目内容、家长反馈、运营交付和品牌信任上。

这意味着新祥编程不能长期定位为“收费版 Scratch”或“闭源 Scratch 改造版”，而应定位为：

> 基于开源 Scratch 技术栈的少儿创意编程启蒙服务，帮助孩子完成第一个作品，并让家长看见成长。

## 2. 战略边界

公开源码仓库管理方案见：`docs/zhimeng-public-source-repo-management.md`。当前核心仓库不变；另建公开源码仓库，只导出 AGPL 对应源码和必要公开文档，`docs/` 按白名单导出，不整体公开。

### 2.1 主动公开的代码

以下内容按“迟早公开”管理，开发时不得把商业秘密、密钥或真实用户数据写入这些代码：

- `scratch-gui` 基础改造、UI、品牌入口、锁定体验和订阅入口。
- Electron 客户端、打包配置、帮助菜单、源码披露入口。
- 与 AGPL 客户端直接组成同一运行版本的构建脚本、测试脚本和发布元数据检查。
- AGPL/GPL 相关依赖的本地修改，例如 `scratch-vm`、`scratch-blocks`、`scratch-render`、`scratch-storage` 等。
- 用于履行源码披露的文案、NOTICE 和必要公开说明。官网销售页、支付页、下载元数据不默认进入公开源码仓库。

执行要求：

- 每个公开安装包都能追溯到对应源码版本。
- 官网页脚、客户端帮助菜单、README 和发布说明指向同一源码地址。
- 发布前检查公开仓库中不存在 `.env`、证书、私钥、真实订单或用户数据。

### 2.2 必须隔离的私有资产

以下内容不得进入公开源码仓库，也不得写死在客户端：

- 真实 `.env`、数据库密码、支付密钥、OSS/CDN key、JWT secret、后台管理 token。
- Apple/Windows 签名证书、私钥、profile、notarization 凭据。
- 用户账号、孩子作品、订单、付款凭证、客服记录、运营备注、利润成本数据。
- 未发布品牌资产、商标申请材料、渠道合同、素材采购授权凭证。
- AI 服务 key、模型成本控制策略、风控规则、内部 prompt 策略。

执行要求：

- 公开仓库只保留 `.env.example` 和脱敏配置说明。
- 生产密钥只存在服务器、CI secret 或本机受保护存储中。
- 运营数据放在数据库、后台或私有表格中，不进入 AGPL 对应源码包。

### 2.3 尽量服务端化的商业能力

AGPL 客户端公开后，任何前端付费墙都可被修改。因此以下能力必须由服务端做最终判断：

- 账号登录、订阅状态、到期时间、冻结状态。
- 设备绑定、设备上限、解绑审批。
- 项目数量、云保存空间、素材权限、协作权限。
- AI 调用次数、AI 功能开关、模型路由和成本控制。
- 家长报告、作品集、学习路径、陪跑进度。
- 退款风险、渠道归因、利润成本、复购跟进。

执行要求：

- 客户端只负责展示和调用，不负责最终授权判定。
- 所有付费权益接口都要校验用户、设备、订阅、套餐和状态。
- 客户端离线或接口失败时，不默认放开高级权益。

## 3. 四层产品架构

### 3.1 开源层

目标：把 AGPL 合规变成可信资产，而不是发布风险。

范围：

- 桌面客户端源码。
- 基础编辑器改造。
- 构建、打包、测试、源码披露说明。
- 官网公开下载和源码链接。

近期任务：

- 建立发布版本到源码 tag 的对应规则。
- 在 release checklist 中加入源码链接、LICENSE、NOTICE、敏感文件扫描。
- 对 README、官网页脚、客户端帮助菜单做一致性检查。

验收标准：

- 用户能从官网或客户端找到当前版本源码。
- 源码版本能构建出同一产品线的客户端。
- 公开仓库不含生产密钥和真实用户数据。

### 3.2 服务层

目标：把付费能力和用户价值放在服务端，避免客户端开源后商业控制失效。

范围：

- Auth / entitlement / device binding。
- 订单、付款凭证、人工确认、退款标记。
- AI 辅助、云保存、素材授权、家长报告。
- 运营后台和利润看板。

近期任务：

- 保持所有解锁判断以服务端 entitlement 为准。
- 梳理服务端 API 与 AGPL 客户端之间的边界，避免把密钥、商业规则写进客户端。
- 将 AI、云保存、素材、高级报告设计为独立服务能力，通过 API 提供。

验收标准：

- 修改客户端前端代码不能绕过服务端套餐和授权校验。
- 服务端能独立记录套餐、成本、交付状态和复购线索。
- 生产环境密钥不出现在客户端包和公开源码中。

### 3.3 内容层

目标：从“卖编辑器”升级为“卖孩子能完成作品的路径”。

范围：

- 新手项目模板。
- 7 天入门任务。
- 作品案例库。
- 高级素材包。
- AI 项目建议和作品点评。
- 家长可见成长记录。

近期任务：

- 先做 5-10 个首发项目模板，覆盖故事、动画、小游戏、互动贺卡、角色对话。
- 将 7 天项目陪跑包和客户端内的新手入口对齐。
- 为每个项目设计“完成标准”和家长能看懂的成果描述。

验收标准：

- 首批用户 7 天内至少 5 个孩子完成第一个作品。
- 家长能在客服/运营触达中看到孩子完成了什么。
- 699 元陪跑包的交付内容能被复盘和复制。

### 3.4 运营层

目标：形成别人复制代码也难复制的成交、交付和复购能力。

范围：

- 私域种子用户。
- 199 元家庭年卡。
- 699 元 7 天项目陪跑包。
- 订单利润记录、交付 SOP、家长回访。
- 品牌、商标、客服信任、下载与安装支持。

近期任务：

- 继续以 20-50 个真实付费家庭为第一验证目标。
- 用 199 元年卡降低首购门槛，用 699 元陪跑包验证利润。
- 在运营台或跟踪表中记录获客成本、交付成本、退款风险、作品完成、下次跟进。

验收标准：

- 首批 20 个种子家庭中真实付费不少于 5 个。
- 付款后 24 小时内人工确认率 100%。
- 每一单都能回看收入、成本、利润、交付状态和复购机会。

## 4. 分阶段实施路线

### 阶段 0：合规与安全基线

目标：公开不慌，私密不漏。

任务：

- 检查公开仓库中是否存在真实 `.env`、密钥、证书、支付凭证和用户数据。
- 补齐 `LICENSE`、AGPL 源码披露、README、官网页脚、客户端帮助菜单之间的一致性。
- 为每个公开安装包建立 release tag 或 commit hash 对应关系。
- 将源码披露检查加入发布前 checklist。

产出：

- 可公开的源码仓库。
- 可复用的源码披露文案。
- 敏感信息排查清单。

### 阶段 1：服务端权益收口

目标：客户端公开后，付费能力仍由服务端控制。

任务：

- 梳理登录、订阅、设备、冻结、过期、套餐能力的服务端校验点。
- 确认客户端只是展示锁定/解锁状态，不承载最终商业判断。
- 将未来 AI、云保存、素材授权、家长报告统一纳入服务端 feature flag 或套餐能力模型。
- 明确接口失败、离线、token 过期时的默认行为。

产出：

- 权益校验清单。
- 服务端 feature/entitlement 设计补充。
- 客户端绕过风险清单。

### 阶段 2：首批可售闭环

目标：先验证真实付费和首次作品完成。

任务：

- 继续主推家庭年卡 199 元/年。
- 小范围开放 7 天项目陪跑包 699 元/期。
- 官网、客户端订阅中心、客服话术、运营台保持同一套餐和价格。
- 每个付费家庭记录付款、开通、首次使用、作品完成、退款风险和复购线索。

产出：

- 20-50 个种子家庭验证数据。
- 首批作品案例。
- 年卡与陪跑包利润复盘。

### 阶段 3：内容和 AI 增值

目标：把付费理由从“能用编辑器”升级为“孩子能持续完成作品”。

任务：

- 上线 5-10 个首发项目模板。
- 设计项目完成标准、家长成果描述和作品截图/展示流程。
- 规划 AI 项目建议、卡住提示、作品点评的服务端 API。
- 将 AI 次数、项目包、素材包纳入套餐权益。

产出：

- 项目模板库。
- 首个家长可见成果机制。
- AI 辅助能力 API 方案。

### 阶段 4：家庭学习体系

目标：形成续费、升级和复购。

任务：

- 建立孩子作品集、学习里程碑和家长报告。
- 推出阶段化项目包和更高阶陪跑套餐。
- 根据真实数据评估 399/699/999+ 元产品结构。
- 在家庭端验证成立后，再考虑机构和渠道包。

产出：

- 可续费的家庭学习路径。
- 可增购的项目包。
- 渠道/机构扩展前置条件清单。

## 5. 决策原则

- 不把 Scratch 作为售卖品牌，只在开源合规和必要技术说明中出现。
- 不宣传未交付的云保存、社区、自动支付、长期一对一课程。
- 不把客户端隐藏按钮当付费控制，所有关键权益以服务端为准。
- 不把源码公开当损失，公开代码换合规和信任，收费服务换收入和利润。
- 不急于重构闭源技术栈，先验证家庭端付费、首次作品和陪跑交付。
- 不用营收掩盖成本，所有商业复盘都要记录获客、交付、退款和支持成本。
