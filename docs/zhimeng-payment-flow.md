# 知萌：购买与支付流程

## 目标

让用户通过下载页完成“下载 - 安装”，并在客户端内完成“登录 - 创建订单 - 付款凭证 - 开通”闭环。

## 推荐路径（MVP：客户端内置购买 + 人工确认）

1. 用户访问下载页
2. 下载 Windows 安装包
3. 打开客户端并登录知萌账号
4. 未开通用户停留在锁定体验，点击“订阅解锁”打开客户端订阅中心
5. 订阅中心创建订单，展示固定收款二维码、订单号、应付金额和付款备注格式
6. 用户扫码付款后在客户端提交付款凭证
7. 运营核对到账记录，并通过人工确认接口开通 entitlement
8. 用户回到客户端点击“刷新订单/授权”，状态 active 后解锁完整编辑器

详细实施计划见 [`docs/zhimeng-manual-qr-payment-plan.md`](./zhimeng-manual-qr-payment-plan.md)。

## 客户端内置购买 vs 网页下单

- **客户端内置购买（当前 MVP 主路径）**
  - 优点：未付费用户不离开产品主上下文，订单、二维码、付款凭证、刷新授权都在同一处完成。
  - 缺点：仍需人工确认到账，客户端需处理 pending/fulfilled/失败文案。
- **网页下单**
  - 仅保留为本地验收、客服辅助或 pay_url 兜底，不再作为官网主购买入口。

MVP 结论：使用“客户端订阅中心创建订单 + 静态二维码收款 + 客户端提交付款凭证 + 运营人工确权”模式。该模式优先保证早期能收款和能开通，暂不依赖真实支付网关回调。`purchase.html` 降级为本地验收/客服辅助页；`pay.html` 保留为订单专属付款兜底页。

## 支付渠道接入要点

- 方案 A（当前 MVP）：
  - 使用商家固定收款二维码
  - 用户提交付款凭证：微信记录转账单号；支付宝记录订单号和商家订单号
  - 运营人工核账并确认订单
  - 交易尾号只用于辅助检索，最终以收款方账单实际到账为准
  - 后端必须保证人工确认幂等、交易号唯一、金额校验和审计留痕
- 方案 B（后续自动化）：
  - 微信支付需企业主体与商户号
  - 支付宝需企业主体与应用签约
  - 生成订单专属二维码，并配置支付回调地址与签名校验

## 订单与 entitlement 关联策略

1. 订单创建时绑定 `user_id`
2. 运营人工确认到账后，服务端更新 entitlement（状态、到期时间、套餐特性）
3. 客户端在登录或手动刷新时拉取最新 entitlement

## 客户端文案建议

- 未登录：`登录并订阅后可进入完整编程编辑器`
- 已登录未订阅：`当前账号未开通订阅，订阅解锁`
- 已过期：`订阅已到期，续费后恢复完整能力`
