# 新祥编程首批 20 个家庭执行手册

## 1. 目标

首批 20 个家庭不是为了“热闹”，而是验证新祥编程能不能形成真实赚钱闭环。

核心验证：

- 家长是否愿意为家庭年卡 199 元付费。
- 家长是否愿意为 7 天项目陪跑包 699 元付费。
- 孩子是否能在 7 天内完成 1-3 个入门作品。
- 每一单扣除获客、佣金、交付、客服、退款风险后是否仍有利润。

## 2. 本轮验收指标

| 指标 | 目标 |
| --- | ---: |
| 触达家庭 | 20 |
| 下载客户端 | >= 10 |
| 注册账号 | >= 8 |
| 创建订单 | >= 6 |
| 真实付款 | >= 5 |
| 购买 7 天项目陪跑包 | >= 3 |
| 完成第一个作品 | >= 3 |
| 完成 3 个作品 | >= 2 |
| 付款后 24 小时内确认 | 100% |
| 陪跑包平均交付耗时 | <= 2 小时/家庭 |

## 3. 20 个家庭分组

| 组别 | 数量 | 来源 | 目标 |
| --- | ---: | --- | --- |
| A 组 | 5 | 熟人/朋友家庭 | 快速跑通完整流程，拿到第一批反馈 |
| B 组 | 5 | 微信群/社群 | 验证陌生一点的家长是否理解卖点 |
| C 组 | 5 | 转介绍 | 验证推荐是否能降低信任成本 |
| D 组 | 5 | 老师/KOL/小机构推荐 | 验证后续渠道包是否有空间 |

## 4. 每日动作

| 天数 | 运营动作 | 目标 |
| --- | --- | --- |
| D1 | 触达 5 个家庭，发官网和下载说明 | 至少 2 个下载 |
| D2 | 跟进安装/注册问题，推动创建订单 | 至少 2 个订单 |
| D3 | 核对付款和开通，推荐第一个作品 | 至少 1 个真实付款 |
| D4 | 推 7 天项目陪跑包，说明 3 个作品目标 | 至少 1 个陪跑意向 |
| D5 | 跟进作品截图和卡点 | 至少 1 个孩子完成作品 |
| D6 | 收集家长反馈、记录阻塞和退款风险 | 明确可优化点 |
| D7 | 复盘成交、利润、作品完成、复购意向 | 决定是否扩大下一批 |

## 5. 家庭级执行步骤

每个家庭按以下顺序推进：

1. 记录来源、孩子年龄、系统环境。
2. 发官网和下载入口。
3. 确认是否下载、安装、注册。
4. 引导进入客户端订阅中心。
5. 创建订单并扫码付款。
6. 提交付款凭证。
7. 运营台确认到账并开通。
8. 引导完成第一个作品。
9. 推荐 7 天项目陪跑包。
10. 陪跑期间记录 Day、完成作品、风险等级、下次跟进。
11. 收集作品截图、家长反馈和是否愿意推荐。

## 7. 判断规则

可以扩大下一批：

- 20 个家庭中至少 5 个真实付费。
- 至少 3 个家庭愿意认真了解陪跑包。
- 陪跑包至少成交 3 单。
- 交付没有明显失控，平均每个陪跑家庭不超过 2 小时。
- 家长能说清楚“新祥编程帮孩子做出了什么”。

必须暂停优化：

- 家长普遍不理解为什么付费。
- 下载/安装/注册卡住超过 30%。
- 付款后人工确认引发不信任。
- 陪跑包成交少于 2 单。
- 陪跑交付明显变成一对一重服务。
- 孩子完成作品比例过低。

## 8. 每周输出

每周至少沉淀：

- 3 个家长原话反馈。
- 3 个孩子作品截图或作品说明。
- 1 份流失原因列表。
- 1 份真实利润复盘。
- 1 个官网或客户端文案优化点。
- 1 个 7 天陪跑 SOP 优化点。
