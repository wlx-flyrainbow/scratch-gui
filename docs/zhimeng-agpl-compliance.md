# 知萌：AGPL-3.0-only 合规方案（执行版）

## 现状确认

- 本仓库 `package.json` 明确为 `AGPL-3.0-only`。
- 基于本仓库进行修改并向用户分发（包括网络服务场景）时，需要提供对应源码。

## 可选路径

1. **继续基于 AGPL 发布（推荐短期）**
   - 对外提供完整对应源码（含你方修改）
   - 保留许可证与版权声明
   - 在下载页/应用内提供源码获取链接
2. **协商商业授权（中长期）**
   - 与权利方沟通商业许可条款
   - 获得书面许可后按商业条款执行
3. **替换底层依赖栈（成本最高）**
   - 以可商业闭源许可栈重构
   - 研发与迁移成本高，不适合 MVP

## 当前项目执行建议

- MVP 阶段按路径 1 执行，保证上线节奏。
- 同步推进路径 2 的沟通，作为后续商业化升级选项。
- 产品与商业落地按 `docs/zhimeng-agpl-product-strategy-implementation-plan.md` 执行：核心编辑器公开，商业能力服务端化，内容与运营形成长期护城河。
- 公开源码发布按 `docs/zhimeng-public-source-repo-management.md` 执行：当前核心仓库不变，另建干净公开仓库，按白名单导出源码和必要文档。

## 发布前核对清单

- [ ] 对外仓库已包含当前运行版本全部对应源码
- [ ] 仓库包含 `LICENSE`，并保留上游版权信息
- [ ] 下载页/应用内提供源码链接与合规声明
- [ ] 版本标签可追溯到线上发布包
